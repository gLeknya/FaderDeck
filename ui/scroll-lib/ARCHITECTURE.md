# ADR-001: fader-scroll — библиотека кастомных скроллов для FaderDeck

**Status:** Proposed
**Date:** 2026-10-01
**Deciders:** Glek
**Рабочее название:** `fader-scroll` (можно переименовать), CSS-префикс `sb-`

---

## 1. Context

FaderDeck написан на vanilla JS, скроллов в интерфейсе много. Нужна мини-библиотека, чтобы быстро делать кастомные скроллы, которые выглядят и ведут себя +- одинаково везде.

Исходные требования:

1. Вертикальные и горизонтальные скроллы; для горизонтального настройка, когда обычное колесо мыши (без Shift) крутит его по горизонтали.
2. Плавное движение ползунка и плавное изменение его размера, когда область растёт или сжимается.
3. Произвольное размещение скролла, независимо от того, где его ставит WebKit по умолчанию.
4. Анимация появления и затухания.
5. Плавное скрытие при бездействии и показ при активности.
6. Детальная кастомизация каждого пункта.

Ограничения: vanilla JS, чистый ESM без зависимостей, современные браузеры (Chromium, Firefox, Safari), отдельный репозиторий. React-обёртка не входит в v1.

---

## 2. Decision (кратко)

Контент скроллится **нативно**, родной скроллбар скрыт, а библиотека рисует свои `track` и `thumb` как отдельные DOM-элементы и синхронизирует их со скроллом. Анимацией ползунка и появления управляет **один JS-движок**. Вид настраивается через **CSS-переменные и классы**, поведение через **JS-опции**. Подключение через `createScroll(el, opts)` или `data-scroll`, общий вид через `setDefaults` и пресеты.

## 3. Options Considered

| # | Вопрос | Выбрано | Отвергнуто (почему) |
|---|--------|---------|---------------------|
| 1 | Механизм скролла | Нативный скролл + свой ползунок; задел под `smoothWheel` в будущем | Полностью виртуальный скролл: надо переизобретать тач, клавиатуру, `sticky`, поиск, доступность |
| 2 | Размещение трека | Внутри host по умолчанию (позиция через CSS-переменные) + опция `mount` для внешнего элемента | Только внутри host: нельзя вынести трек из рамки; только `mount`: слишком много ручной работы |
| 3 | Плавность | Один JS-движок (сглаживание позиции и длины, rAF только при движении) | Чистый CSS `transition`: дёргается при быстром скролле, нет пружины, позиция и размер рассинхронизируются; гибрид: два механизма |
| 4 | Показ и скрытие | Режимы + триггеры + тайминги; движок отдаёт `--sb-presence` (0..1) | Один режим «авто»: мало гибкости; без `--sb-presence`: анимации зашиты в библиотеку |
| 5 | API | Императивное ядро + `data-scroll` + `setDefaults` и пресеты | Только императивный: скроллы разъезжаются по виду; только декларативный: магия и слежение за DOM |
| 6 | Кастомизация | Вид в CSS (переменные + классы), поведение в JS-опциях | Всё в JS: неудобно для градиентов, теней, состояний, тем; всё в CSS: поведение не выразить |
| 7 | Колесо в горизонтальном скролле | `horizontalWheel: 'shift' \| 'always' \| 'auto'` | Булев флаг: залипание страницы и нет варианта для двух осей; настраиваемый модификатор: избыточно |
| 8 | Поставка | Отдельный репозиторий, ESM без зависимостей, демо, `node --test` для чистого ядра, README | Без тестов: хрупко; Playwright e2e: тяжело для мини-библиотеки |

## 4. Architecture

### 4.1 Структура репозитория

```
fader-scroll/
  package.json            # "type": "module", exports, scripts: test, demo
  README.md               # установка, быстрый старт, полный API, список CSS-переменных
  src/
    index.js              # публичные экспорты
    core/                 # чистая логика, без DOM, тестируется в Node
      geometry.js         # размер и позиция ползунка, обратное преобразование
      engine.js           # движок сглаживания и tween (инжектируемые часы)
      visibility.js       # машина состояний показа и скрытия
      wheel.js            # решение, что делать с событием колеса
      options.js          # дефолты, слияние, валидация, реестр пресетов
      attrs.js            # разбор data-scroll-* в объект опций (без DOM)
    dom/
      scroll.js           # createScroll: сборка всего вместе, публичный экземпляр
      structure.js        # host, track, thumb, скрытие родного скроллбара, откат
      observers.js        # ResizeObserver, MutationObserver (childList), scroll, matchMedia
      drag.js             # перетаскивание ползунка, клик по треку
      scheduler.js        # общий rAF: один цикл на все экземпляры
      declarative.js      # initScrolls(root)
  styles/
    fader-scroll.css      # базовые стили и дефолтные значения переменных
  demo/
    index.html, demo.js, demo.css
  scripts/
    serve.js              # крошечный статический сервер на встроенном http (для демо)
  test/
    geometry.test.js, engine.test.js, visibility.test.js,
    wheel.test.js, options.test.js, attrs.test.js
```

Принцип: всё, что можно, живёт в `core/` как чистые функции с инжектируемыми зависимостями (часы, размеры). `dom/` только измеряет, слушает события и пишет в DOM.

### 4.2 DOM-структура

```html
<div class="sb-host sb-has-y">                  <!-- host: создаётся библиотекой или уже есть (родитель с .sb-host) -->
  <div class="sb-viewport your-own-classes">    <!-- el: скроллится нативно, сохраняет identity и scrollTop/scrollLeft -->
    ...контент...
  </div>
  <div class="sb-track sb-y" aria-hidden="true">
    <div class="sb-thumb"></div>
  </div>
  <!-- при axis: 'x' | 'both' добавляется .sb-track.sb-x -->
</div>
```

- `el` остаётся тем самым скроллящимся элементом: существующий код с `el.scrollTop` не ломается, дети не переносятся.
- Если родитель `el` уже имеет класс `sb-host`, библиотека использует его как host и ничего не оборачивает. Иначе создаёт host и ставит его на место `el`.
- Родной скроллбар скрывается на `el`: `scrollbar-width: none; -ms-overflow-style: none;` и `::-webkit-scrollbar { display: none }`.
- Родной скроллбар не занимает место, поэтому скролл всегда **overlay** (резервировать место пользователь может сам через `padding` у `el`).
- Для `mount` трек создаётся в указанном элементе, а не в host; состояния и `--sb-*` читаются от самого трека.

### 4.3 Геометрия (`core/geometry.js`)

Для одной оси: `viewport` (clientHeight/clientWidth), `content` (scrollHeight/scrollWidth), `scroll` (scrollTop/scrollLeft), `track` (длина трека вдоль оси), `minThumb` (px).

```
maxScroll  = max(0, content - viewport)
scrollable = maxScroll > 0.5                       // эпсилон против дробных размеров и zoom
size       = clamp(track * viewport / content, min(minThumb, track), track)
offset     = scrollable ? clamp(scroll / maxScroll, 0, 1) * (track - size) : 0   // clamp гасит резиновый overscroll в Safari
scrollFromOffset(offset) = (offset / (track - size)) * maxScroll                 // для перетаскивания
```

### 4.4 Движок (`core/engine.js`)

Каналы значений: `offset`, `size`, `presence`.

- `offset` и `size`: экспоненциальное сглаживание, независимое от частоты кадров: `alpha = 1 - exp(-dt / tau)`; значение подтягивается к цели; если `|target - value| < 0.1px`, значение прилипает к цели. `tau` в мс задаётся опцией `smoothing` (0 = без сглаживания).
- `presence`: tween по времени (`fadeIn` / `fadeOut` мс, easing); при развороте посреди анимации продолжает от текущего значения.
- Перетаскивание обходит сглаживание: `offset` прилипает к указателю сразу.
- rAF работает только пока хоть один канал не достиг цели. Общий планировщик (`dom/scheduler.js`): один rAF на все экземпляры, один проход за кадр: сначала чтение (измерения), потом запись (CSS-переменные).
- Часы и «step» инжектируются, чтобы тестировать без браузера: `step(state, target, dt, params) -> state`.

Вывод в DOM: движок пишет **CSS-переменные на элемент трека** (только если значение изменилось заметно): `--sb-thumb-offset` (px), `--sb-thumb-size` (px), `--sb-presence` (0..1). Базовый CSS потребляет их: `transform: translateY(var(--sb-thumb-offset))` / `translateX(...)`, `height` / `width: var(--sb-thumb-size)`, `opacity: var(--sb-presence)`.

### 4.5 Видимость (`core/visibility.js`)

Машина состояний; вход: события и время, выход: целевое `presence` (0 или 1).

- `never`: цель всегда 0.
- `always`: цель 1.
- `hover`: цель 1, пока курсор над host или над треком или идёт перетаскивание; иначе 0 (после `idleDelay`).
- `auto`: любая включённая активность ставит цель 1 и перезапускает таймер `idleDelay`; по истечении цель 0. Пока курсор над треком или идёт перетаскивание, не гаснет.
- Поверх всего: если нет переполнения и `hideWhenNoOverflow: true`, цель 0 в любом режиме.
- Триггеры (`triggers`, каждый можно выключить): `scroll`, `hoverHost`, `hoverTrack`, `drag`, `resize`.
- Часы инжектируются (тесты на фейковом времени).
- Когда `presence` дошёл до 0, на трек ставится `.sb-hidden` (`visibility: hidden; pointer-events: none`).

### 4.6 Колесо (`core/wheel.js`)

Чистая функция `decideWheel(input) -> { handled, dx, dy }`.

- Не трогаем: `ctrlKey` (зум), горизонтальные жесты (`|deltaX| >= |deltaY|`, трекпад), `shiftKey` (браузер сам конвертирует), режим `shift`, ось без `x`.
- `always`: если по `deltaY` элемент реально может прокрутиться по горизонтали в этом направлении, прокручиваем `scrollLeft` и `preventDefault`; на краю событие уходит выше (страница не залипает).
- `auto`: как `always`, но только если у элемента нет вертикального переполнения; иначе нативное поведение.
- Учитываем `deltaMode` (строки и страницы приводятся к px).
- Слушатель `wheel` с `{ passive: false }` ставится только если `horizontalWheel !== 'shift'` и ось включает `x`.
- Предупреждение для README: `always` на двухосевом элементе отнимает вертикальное колесо, для таких случаев нужен `auto`.

### 4.7 Перетаскивание и клик по треку (`dom/drag.js`)

- Pointer Events + `setPointerCapture` на ползунке, `touch-action: none` на ползунке.
- Во время перетаскивания: класс `.sb-dragging`, `presence` держится на 1, у `el` временно `scroll-behavior: auto`, сглаживание `offset` обходится.
- Клик по треку (не по ползунку): опция `trackClick`: `'page'` (по умолчанию, сдвиг на 0.9 размера viewport в сторону клика), `'jump'` (ползунок центрируется на точке клика), `'none'`.
- Тач: скролл нативный, ползунок показывается по триггеру `scroll`, hover-триггеры не участвуют.

### 4.8 Наблюдатели (`dom/observers.js`)

- `scroll` (passive) на `el`: обновляет цель `offset`.
- `ResizeObserver` на `el` и на каждого прямого ребёнка `el`; `MutationObserver` только по `childList` у `el`, чтобы подключать и отключать наблюдение за детьми. Это ловит рост и сжатие контента; обновляет цели `size` и `offset`, и движок плавно догоняет.
- Для случаев, когда рост контента не виден наблюдателям, есть публичный `update()`.
- `matchMedia('(prefers-reduced-motion: reduce)')`: при `reducedMotion: 'respect'` сглаживание и fade сводятся к 0 мс.
- Элементы с `display: none` и нулевым размером пропускаются, пока `ResizeObserver` не сообщит, что они появились.

## 5. Public API

```js
import { createScroll, initScrolls, setDefaults, definePreset, getInstance } from 'fader-scroll';
import 'fader-scroll/styles/fader-scroll.css';   // или <link>, JS стили сам не подключает

const sb = createScroll(el, { axis: 'both', visibility: 'auto' });
sb.update();                      // принудительно перемерить
sb.setOptions({ idleDelay: 1500 });
sb.on('show', fn);                // 'scroll' | 'show' | 'hide' | 'update' | 'dragstart' | 'dragend' | 'overflowchange'
sb.off('show', fn);
sb.getState();                    // { x?: {...}, y?: {...} }, только чтение
sb.destroy();                     // снимает всё, возвращает DOM как было (если host создали мы, он разворачивается)

setDefaults({ visibility: 'auto', idleDelay: 900 });     // общий вид и поведение для всего приложения
definePreset('thin', { options: { minThumb: 16 }, className: 'sb-theme-thin' });
createScroll(el, { preset: 'thin' });

initScrolls(document);            // находит [data-scroll], один раз, без слежения за DOM
getInstance(el);                  // существующий экземпляр или null
```

- Повторный `createScroll` на том же `el` возвращает существующий экземпляр.
- Порядок приоритета опций: встроенные дефолты < `setDefaults` < пресет < `data-scroll-*` < явные `opts`.

### Декларативный вариант

```html
<div data-scroll="y" data-scroll-visibility="always" data-scroll-preset="thin"></div>
<div data-scroll="x" data-scroll-horizontal-wheel="auto" data-scroll-mount-x="#my-rail"></div>
```

`data-scroll` принимает `y | x | both`. Остальные `data-scroll-*` это kebab-case версии опций; значения приводятся к числу, булеву, строке; объекты передаются JSON. Разбор в `core/attrs.js` принимает обычный объект (как `dataset`), чтобы тестироваться без DOM.

## 6. JS-опции (поведение)

| Опция | Значения | По умолчанию |
|-------|----------|--------------|
| `axis` | `'y' \| 'x' \| 'both'` | `'y'` |
| `mount` | элемент, селектор или `{ x, y }` | `null` (трек внутри host) |
| `visibility` | `'auto' \| 'always' \| 'hover' \| 'never'` | `'auto'` |
| `triggers` | `{ scroll, hoverHost, hoverTrack, drag, resize }` (булевы) | все `true` |
| `idleDelay` | мс | `900` |
| `fadeIn` / `fadeOut` | мс | `120` / `350` |
| `easing` | имя (`'ease-out'`, `'linear'`, ...) или функция `t => t` | `'ease-out'` |
| `hideWhenNoOverflow` | boolean | `true` |
| `smoothing` | число (мс, `tau`) или `{ offset, size }` | `{ offset: 80, size: 140 }` (0 = выключено) |
| `minThumb` | px | `24` |
| `horizontalWheel` | `'shift' \| 'always' \| 'auto'` | `'shift'` |
| `trackClick` | `'page' \| 'jump' \| 'none'` | `'page'` |
| `animation` | `'fade' \| 'slide' \| 'scale' \| 'none'` (ставит класс `sb-anim-*`) | `'fade'` |
| `reducedMotion` | `'respect' \| 'ignore'` | `'respect'` |
| `preset` | имя пресета | `null` |
| `className` | класс темы на host | `''` |

Опции валидируются: неизвестные ключи и значения вне допустимых дают понятную ошибку (в dev) и откат к дефолту.

## 7. Вид: CSS-переменные и классы

Переменные можно задавать на host, на любом предке, в теме или пресете (`className`). Для `mount` читаются от элемента, в который смонтирован трек.

**Входные (задаёт пользователь):**

| Переменная | По умолчанию | Что делает |
|------------|--------------|------------|
| `--sb-thickness` | `6px` | толщина трека и ползунка |
| `--sb-thickness-active` | `10px` | толщина при наведении на трек и при перетаскивании |
| `--sb-thickness-transition` | `120ms` | скорость смены толщины |
| `--sb-track-bg` | `transparent` | фон трека (любой CSS: цвет, градиент) |
| `--sb-track-radius` | `999px` | скругление трека |
| `--sb-thumb-bg` | `rgb(128 128 128 / .55)` | фон ползунка (в том числе градиент) |
| `--sb-thumb-bg-hover` | `rgb(128 128 128 / .75)` | при наведении |
| `--sb-thumb-bg-active` | `rgb(128 128 128 / .9)` | при перетаскивании |
| `--sb-thumb-radius` | `999px` | скругление ползунка |
| `--sb-thumb-border` | `none` | рамка ползунка |
| `--sb-thumb-shadow` | `none` | тень ползунка |
| `--sb-y-top`, `--sb-y-bottom`, `--sb-y-right`, `--sb-y-left` | `4px`, `4px`, `2px`, `auto` | положение вертикального трека |
| `--sb-x-left`, `--sb-x-right`, `--sb-x-bottom`, `--sb-x-top` | `4px`, `4px`, `2px`, `auto` | положение горизонтального трека |
| `--sb-corner-gap` | `calc(var(--sb-thickness-active) + 4px)` | отступ у угла, когда есть обе оси (класс `sb-has-both`) |
| `--sb-z` | `10` | z-index трека |

**Выходные (пишет библиотека на трек, только чтение):** `--sb-thumb-offset`, `--sb-thumb-size`, `--sb-presence`.

**Классы.** Host: `sb-host`, `sb-has-x`, `sb-has-y`, `sb-has-both`, `sb-scrollable-x`, `sb-scrollable-y`, `sb-active` (недавняя активность), `sb-hover`, `sb-dragging`, `sb-anim-<name>`, класс темы. Трек: `sb-track`, `sb-x` / `sb-y`, `sb-visible` (`presence > 0`), `sb-hidden` (`presence == 0`), `sb-hover`, `sb-dragging`. Ползунок: `sb-thumb`.

Базовое отображение `--sb-presence`: `fade` это `opacity`, `slide` это сдвиг трека к краю (`translate`), `scale` это `scale` по поперечной оси. Свои анимации пишутся CSS-ом поверх `--sb-presence`.

## 8. Граничные случаи

- Нет переполнения: трек скрыт (если `hideWhenNoOverflow`), иначе ползунок на всю длину трека.
- Контент сжался, пока скролл был внизу: нативный скролл сам зажмётся; пересчёт идёт по `ResizeObserver`.
- Overscroll (резиновый эффект Safari): `offset` зажимается в диапазоне, ползунок не вылезает из трека.
- Дробные размеры и браузерный zoom: эпсилон 0.5px в проверке переполнения.
- `minThumb` больше длины трека: ползунок равен длине трека.
- Нет ни одного размера (скрытый элемент): пересчёт откладывается до первого ненулевого измерения.
- `destroy()`: убирает слушатели и наблюдатели, останавливает rAF, удаляет track/thumb, снимает классы и стили, разворачивает созданный host.
- Вложенные скроллы независимы; перехват колеса только для собственного `el`.
- Повторный `initScrolls` идемпотентен.

## 9. Решения, принятые без обсуждения (проверь и поправь)

1. Имя библиотеки `fader-scroll` и CSS-префикс `sb-`.
2. Host: если родитель уже `.sb-host`, используем его; иначе оборачиваем `el` сами. Для flex- и grid-элементов обёртку нужно ставить вручную (автоматический host сохраняет раскладку только для блочных элементов).
3. Скролл всегда overlay (место под него не резервируется).
4. CSS подключается отдельным файлом, JS стили сам не вставляет.
5. Сглаживание по умолчанию короткое (`offset: 80 мс`), чтобы ползунок не отрывался от контента заметно.
6. `trackClick: 'page'` по умолчанию, без «зажать и повторять».
7. Дефолтные цвета нейтральные серые (под тёмную и светлую темы), FaderDeck-вид задаётся пресетом или темой.
8. Скролл всей страницы (`html` / `body`) в v1 не поддерживается.

## 10. Trade-off Analysis

- **Нативный скролл против виртуального.** Получаем надёжность (тач, клавиатура, поиск, `sticky`) ценой того, что контент скроллится ступеньками браузера, а плавным можно сделать только ползунок.
- **Сглаживание ползунка.** Чем больше `tau`, тем плавнее, но тем сильнее ползунок «отстаёт» от контента. Поэтому короткий дефолт и возможность выключить.
- **CSS-переменные на треке каждый кадр.** Дёшево, пока поддерево маленькое (трек + ползунок), и даёт пользователю полный контроль над видом.
- **Обёртка в host.** Минус: ломает раскладку у flex- и grid-элементов, плюс: `el` и его содержимое остаются нетронутыми.

---

## 11. Consequences

- Проще: единый вид через `setDefaults` и пресеты; любой скролл подключается одной строкой или атрибутом; произвольное размещение и любые анимации появления через CSS.
- Сложнее: поддерживать два слоя настройки (CSS и JS), следить за границей «что где»; автоматический host не подходит для каждого раскладочного случая.
- Пересмотреть позже: `smoothWheel` (плавная прокрутка контента), резервирование места (gutter), RTL, React-обёртка, скролл страницы целиком, «зажать и повторять» на треке.
